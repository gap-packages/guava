In this file we record the changes since the first GAP 4 release of
the GUAVA package.

## 3.22 (2026-09-19)

- Decode and Decodeword now agree on which word they return: Decode gives
  the information word, Decodeword the nearest codeword. Every special
  decoder -- Hamming, cyclic, BCH and generalized Reed-Solomon -- returned
  the wrong one of the two in some case (issue #126)
- Fix the generalized Reed-Solomon interpolation decoder, which used the
  two halves of the interpolating polynomial the wrong way round and so
  returned a word unrelated to the input (issue #12)
- The BCH decoder no longer divides by zero, or silently returns a word
  that is not in the code, when given more than (d-1)/2 errors. It reports
  "not decodable", as it already did for other undecodable input
  (issue #41)
- Decode BCH codes whose roots do not start at a^1, which previously
  failed with "no method found"
- Fix Codeword looping forever on an empty list, which encoding the zero
  information word into a cyclic code ran into
- RootsCode computes the BCH bound it always claimed to. It compared
  cyclotomic cosets where it meant exponents, so the bound came out as 2
  whatever the input; over a non-prime field it also collected the wrong
  roots entirely (issue #105)
- CyclotomicCosets(q,1) returns the one class there is rather than failing,
  so RootsCode accepts 1 as the only root
- A code with a single generator knows its minimum distance, its codewords
  being that generator's scalar multiples. GeneratorMatCode also records
  the least generator weight as an upper bound
- CodeDistanceEnumerator takes the word as a plain list, the way the
  manual passes it
- Use the library's CosetLeadersMatFFE on GAP 4.16.0 and later, where the
  bugs GUAVA's copy worked around are fixed. The copy is an order of
  magnitude slower over fields of size 4 to 255 (issue #104)
- Minimum weight computation no longer truncates lengths and counts to 16
  bits, which made codes longer than 65535 report 0 or crash (issue #46),
  and it validates the generator matrix file instead of overflowing on it
  (issue #57)
- Fix a call to strcmp that was meant to be strcat, in Leon's randobj
- Build from a single Makefile at the root: no recursive make, and no
  second configure script generated by autoconf (issue #97). C code
  coverage is now reported to codecov
- Fix stale and incorrect examples in the manual
- Various janitorial changes

## 3.13 (2016-01-31)

- Incorporated fixes by Dima Pasechnik.
- Incorporated fixes by Jerome Benoit.
- Fixed bug in MinimumWeight() uncovered by Simon Tinius.
- The infix "in" operator was not working for the case of a codeword
  in a code, when the code was defined by a generator polynomial.
- Fixed BCH decoding
- Changes to the test suite:  moved test files to a separate "tst"
  subdirectory,  added "decoding.tst" file which includes thorough tests
  of decoding algorithms, modified "guava.tst" so that randomization of
  input values does not effect output. Added "hadamard.tst" for testing the
  construction of Hadamard matrices
- Rewrite of the algorithms for constructing Hadamard matrices.  Hadamard
  matrices can be constructed using Sylvester's and Paley's (type I and II)
  methods.  The Paley constructions use properties of the quadratic
  residues in a finite field, which previously was assumed to be of
  prime order - GF(p) - now we can also handle extension fields - GF(p^k).
  The smallest order without a construction is now 92.
- Changes necessitated by switch to GitHub (mostly to the webpage)
- Added ErrorVector() convenience function for creating small weight
   error vectors from a list of error positions (used in testing Decode()
   methods.)
- Cleaned up Decode/Decodeword which are supposed to return info. words
  and corrected codewords respectively.  Many codes with SpecialDecoder
  functions were doing the wrong thing.
- Tested against GAP 4.8.1 and made changes necessitated by GAP updates.
  (E.g. ReadTest -> Test)
